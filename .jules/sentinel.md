## 2024-05-18 - Prevent SSRF in Google Maps link expansion
**Vulnerability:** The `/api/enrich` endpoint accepted user-provided URLs and passed them directly to `fetch()` in the `expandUrl` function without validation. This allowed an attacker to input internal URLs (e.g., `http://169.254.169.254`) or malicious endpoints, turning the server into a proxy for Server-Side Request Forgery (SSRF).
**Learning:** Even when the intended use case is narrow (expanding short links like `maps.app.goo.gl`), if the code uses a user-supplied string in a network request, it must be validated. Using naive `.includes()` or `.startsWith()` for domain validation is insufficient (e.g., `google.attacker.com`).
**Prevention:** Always parse untrusted URLs using the `URL` constructor. Strictly validate protocols (allow only `http:`/`https:`) and hostnames using exact matching (`===`), strict suffix matching (`.endsWith('.google.com')`), or precise regular expressions for expected third-party domains before initiating external HTTP requests. Additionally, avoid exposing raw error messages or stack traces in `catch` blocks that might leak information about internal network failures.
