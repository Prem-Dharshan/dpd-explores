## 2024-05-18 - Fix SSRF in URL Expansion
**Vulnerability:** The `/api/enrich` endpoint was vulnerable to Server-Side Request Forgery (SSRF) when expanding Google Maps URLs (`expandUrl` function). It would follow any redirect provided by an attacker without validating the protocol or hostname, potentially allowing an attacker to make the server perform requests to internal networks or malicious sites. Furthermore, raw error messages were being leaked in the catch block (`String(e)`), providing attackers with debugging information.
**Learning:** URL expansion and redirection logic must strictly validate both the initial URL and every subsequent URL retrieved from the `Location` header. Trusting user input or the redirects of third-party services blindly can lead to SSRF. Also, server errors must fail securely with generic messages for 500 status codes instead of exposing raw error strings.
**Prevention:** Always implement strict protocol validation (allowing only `http:` and `https:`) and strict hostname validation checks before making requests. Avoid naive string matching; use exact matches, `.endsWith` for subdomains, or precise regexes (e.g., `/^((www|maps|consent)\.)?google\.[a-z]{2,3}(\.[a-z]{2})?$/`) for regional domains. Return generic error messages for 500 status codes.
