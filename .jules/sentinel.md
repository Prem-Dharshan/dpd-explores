
## 2025-02-27 - [CRITICAL] Prevent SSRF & Info Leak in URL Expansion
**Vulnerability:** The `/api/enrich` Vercel Serverless Function manually followed redirects using `fetch` with `redirect: "manual"` without validating the target domains. This allowed Server-Side Request Forgery (SSRF) bypasses where a safe-looking Google link could redirect the backend server to arbitrary internal or external domains. In addition, the generic `catch` block leaked raw internal error stack traces directly to the client response via `String(e)`.
**Learning:** Naively trusting user-supplied Google Maps links and following their `Location` headers implicitly trusts the redirect chain. We must validate both the original URL and every subsequent URL in the chain against a strict whitelist of protocols (`http:` / `https:`) and hostnames.
**Prevention:** Implement an explicit `isSafeGoogleUrl` validation function. Use exact checks (`maps.app.goo.gl`) and regexes (`/^((www|maps|consent)\.)?google\.[a-z]{2,3}(\.[a-z]{2})?$/`) instead of loose `.includes()` or `.startsWith()` matches. Validate the URL inside the redirect loop *before* invoking `fetch()`. Additionally, always use type narrowing (`e instanceof Error`) in `catch` blocks and return generic client-facing messages like "An error occurred" to fail securely.
