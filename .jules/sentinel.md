## 2023-10-27 - [Server-Side Request Forgery (SSRF) in URL Enrichment]
**Vulnerability:** The `/api/enrich` endpoint accepted arbitrary URLs for Google Maps resolution and used them in `fetch` with `redirect: "manual"`. Although it followed `Location` headers to expand short links, it did not strictly validate the initial URL or the subsequent redirected URLs against an allowlist, exposing the application to Open-Redirect SSRF where an attacker could query internal IP addresses or arbitrary external domains.
**Learning:** When expanding user-provided URLs by following redirects manually, every URL (both the initial and any from the `Location` header) must be checked against an allowlist of permitted hostnames and protocols to prevent SSRF bypasses.
**Prevention:** Implement an explicit URL validation function (e.g., `isAllowedUrl`) that checks for `http:`/`https:` protocols and strictly regex-matches allowed hostnames (e.g., `maps.app.goo.gl` or `endsWith('.google.com')`). Call this function for every URL in the redirect chain before invoking `fetch`.
