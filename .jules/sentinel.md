## 2024-05-24 - SSRF and Info Leak in Google Maps URL Expansion

**Vulnerability:**
The `/api/enrich` endpoint accepted user-provided URLs in the `url` parameter and attempted to resolve redirects by repeatedly calling `fetch(current, { method: "GET", redirect: "manual" })`. It did not validate the URL's protocol or hostname on the initial input or the subsequent redirected URLs. This created a Server-Side Request Forgery (SSRF) vulnerability where an attacker could provide a URL that eventually redirects to a malicious internal IP or localhost, leading the server to fetch unintended resources. Furthermore, any error during this process or elsewhere in the endpoint was caught and exposed to the client in the 500 response using `String(e)`, which leaks internal server information and stack traces.

**Learning:**
When manually resolving redirects for user-provided URLs, naive fetching is extremely dangerous. It allows for open-redirect SSRF bypasses if the redirect chain leads away from the intended target. The validation logic needs to be strict and applied to *every* step in the redirect chain. When attempting to allowlist Google domains for Google Maps expansion, a naive `.startsWith('google.')` is insufficient because an attacker could use `google.attacker.com`. Regular expressions for hostnames must be precise to only capture valid permutations. Finally, error handlers must fail securely and return generic errors rather than raw exception details to avoid leaking system context.

**Prevention:**
Implemented an explicit `isValidGoogleMapsUrl` validation function. This function asserts the protocol is either `http:` or `https:`. It also enforces strict hostname validation, explicitly allowing exactly `maps.app.goo.gl` or matching a precise regex (`/^((www|maps|consent)\.)?google\.[a-z]{2,3}(\.[a-z]{2})?$/`) for Google domains, preventing circumvention. This validation is invoked on the initial URL and *every single redirect URL* during expansion in `expandUrl`. To address the information leak, the `catch` block was updated to return `res.status(500).json({ error: "An error occurred" })`, masking the specific `String(e)` internal details while still logging the full error to the server console.
