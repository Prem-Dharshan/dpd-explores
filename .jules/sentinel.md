## 2024-05-24 - Fix SSRF in URL enrichment endpoint
**Vulnerability:** A Server-Side Request Forgery (SSRF) vulnerability existed in `api/enrich.ts` where the `expandUrl` function followed redirects by making blind GET requests to user-provided URLs or `Location` headers without strict validation.
**Learning:** Blindly trusting and resolving URLs from users (or from subsequent redirect headers) allows an attacker to direct the server to make requests to arbitrary external domains, internal IPs, or unauthorized protocols (e.g., `file://`), risking information disclosure or internal service exploitation. Naive `.startsWith` checks are insufficient because they can be easily bypassed (e.g., `google.attacker.com`).
**Prevention:** Always implement an explicit protocol validation check (e.g., allow only `http:` and `https:`) and strict hostname validation (using exact match, correct suffix matching like `.endsWith('.google.com')`, or precise regex for regional domains) for both the initial URL and any subsequent redirect URLs before invoking `fetch`.
