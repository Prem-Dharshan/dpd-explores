## 2024-05-18 - SSRF Vulnerability in Google Maps URL Expansion
**Vulnerability:** The application was vulnerable to SSRF (Server-Side Request Forgery) in the `/api/enrich` endpoint. The `expandUrl` function manually followed redirects without verifying if the URLs extracted from the `Location` header were pointing to a safe domain, creating a risk where an attacker could provide a malicious URL that redirects to internal IPs or sensitive internal services.
**Learning:** Even if the initial user input looks like a valid URL, failing to validate subsequent URLs during manual redirect expansion can allow open-redirect SSRF bypasses. The `fetch` API doesn't inherently protect against this when `redirect: "manual"` is used.
**Prevention:** Always implement explicit protocol validation (allowing only `http:` and `https:`) and strict hostname validation checks. Avoid naive string matching like `.startsWith('google.')` and use precise matchers/regexes (e.g., exact matches, `.endsWith('.google.com')` strictly for subdomains) for every URL in the redirect chain, including the final resolved URL.
