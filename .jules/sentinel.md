## 2025-02-24 - Prevent SSRF in Google Maps URL Enrichment
**Vulnerability:** The `/api/enrich` endpoint blindly fetched user-provided URLs in `expandUrl` following redirects, allowing Server-Side Request Forgery (SSRF) and Open Redirect bypasses. The endpoint also leaked internal stack traces via generic `String(e)` error handling.
**Learning:** Naive URL extraction using `expandUrl` without protocol or hostname validation lets users resolve internal network URLs or malicious sites. Blindly using `redirect: "manual"` without validating intermediate `Location` headers can bypass initial input checks.
**Prevention:** Implement strict protocol (`http`/`https`) and hostname validation (e.g., specific Google domains like `maps.app.goo.gl` or regex constraints for regional `.google.com` variants). Validate URLs *before* fetching and validate every subsequent redirected URL. Return targeted `400` errors for validation failures and generic `500` errors for unexpected issues to prevent information leakage.
