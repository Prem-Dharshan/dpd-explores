## 2024-11-03 - Open Redirect SSRF Vulnerability in Google Maps Link Expansion
**Vulnerability:** Server-Side Request Forgery (SSRF) bypass through open redirect handling in `/api/enrich`. The endpoint manually followed redirects using `Location` headers but only loosely checked the initial URL (or did not check it at all before expanding it), allowing an attacker to provide an arbitrary URL or a benign Google URL that redirects to internal IP addresses (e.g., `http://169.254.169.254`).
**Learning:** When using `redirect: "manual"` in `fetch` to expand short links, every subsequent URL extracted from the `Location` header must be strictly validated against an allowlist. A safe initial domain does not guarantee safe redirect targets. Relying on string matching (like `.startsWith()`) is insufficient due to `@` or `#` bypasses.
**Prevention:** Always use the `URL` constructor (`new URL()`) to parse URLs before validation. Implement explicit protocol checks (`http:` and `https:`) and strict hostname allowlists (e.g., exact match or `.endsWith()` for subdomains) for both the initial input and every URL encountered during redirect expansion.
