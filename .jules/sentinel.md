## 2025-03-05 - Fix SSRF and Prompt Injection Vulnerabilities
**Vulnerability:** A critical SSRF (Server-Side Request Forgery) was present in `api/enrich.ts` due to blindly following redirects from user-supplied URLs without domain validation. A Prompt Injection vulnerability was present in `api/categorize.ts` and `api/recommend.ts` by concatenating user data into the system instructions instead of using separate roles. Also, error leakage was observed across all endpoints exposing raw exceptions.
**Learning:** For outbound API endpoints that handle user-provided URLs (especially those expanding shortlinks), each step of the redirect loop must be validated against a strict domain whitelist to prevent an attacker from redirecting the server to internal endpoints or unapproved external domains. User input must always be separated from system instructions when interacting with LLMs.
**Prevention:** Always implement explicit protocol and strict hostname validation (whitelisting allowed domains) on user-provided URLs, and re-apply these checks at every step of a redirect loop. When constructing LLM prompts, strictly separate system instructions using the 'system' role and untrusted user data using the 'user' role. Ensure catch blocks return generic messages for 500 status codes.
