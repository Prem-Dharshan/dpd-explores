## 2024-06-25 - Fix Server-Side Request Forgery (SSRF) in URL expansion
**Vulnerability:** The application was susceptible to SSRF because the `expandUrl` function in `api/enrich.ts` followed redirects manually (using `fetch(url, { redirect: "manual" })`) without validating the initial URL or the URL from the `Location` header in the response. An attacker could supply a URL that redirects to an internal IP address or an unintended service.
**Learning:** Manual redirect handling needs strict validation for every redirect step. Just validating the first URL isn't sufficient to prevent SSRF if the attacker controls the redirect response. It's critical to parse the URL safely (using `new URL()`) and validate both the protocol (http/https) and the hostname against an allowlist.
**Prevention:** Always use a robust URL parsing method (like the `URL` constructor) to extract and check the protocol and hostname. When manually following redirects, re-validate every URL obtained from the `Location` header against a strict allowlist of domains before making the next request.
