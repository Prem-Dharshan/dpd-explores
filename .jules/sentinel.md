## 2024-05-09 - [Fix SSRF vulnerability in Google Maps link expansion]
**Vulnerability:** The `/api/enrich` endpoint accepted arbitrary URLs and followed redirects manually without validating the domain or protocol. This allowed for Server-Side Request Forgery (SSRF) bypasses where a malicious user could provide a URL that redirects to an internal IP or service.
**Learning:** Naive string matching like `.startsWith('google.')` is insufficient for domain validation as it allows subdomains like `google.attacker.com`. Manual redirect following via `fetch` with `redirect: "manual"` requires strict validation of the `Location` header URL at each step.
**Prevention:** Always implement explicit protocol validation (`http:`/`https:`) and strict hostname validation checks (exact matches, `.endsWith('.google.com')` strictly for subdomains, and precise regexes for regional domains). Validate both the initial user-provided URL and every subsequent URL extracted from the `Location` header before following redirects.
