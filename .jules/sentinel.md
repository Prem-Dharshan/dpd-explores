## 2023-10-27 - SSRF Vulnerability in URL Expansion
**Vulnerability:** The `/api/enrich` endpoint was vulnerable to Server-Side Request Forgery (SSRF) because it followed manual redirects (`fetch(url, { redirect: "manual" })`) without validating the initial URL or the subsequent URLs retrieved from the `Location` header against an allowlist.
**Learning:** Manual redirect handling can be used to bypass SSRF protections if an attacker provides a URL to a safe domain that redirects to a malicious internal IP or a disallowed protocol (e.g., `file://` or `gopher://`). It is crucial to validate the protocol and hostname at every step of the redirect chain.
**Prevention:** Always validate both the initial URL and any URLs extracted from the `Location` header during manual redirect resolution. Use strict protocol allowlisting (`http:`, `https:`) and precise hostname validation (e.g., explicit exact matches, strictly checking subdomains via `.endsWith`, or rigorous regular expressions) instead of naive string matching. Use `new URL()` to parse strings to avoid bypasses related to URL parsing discrepancies.
