## 2023-11-01 - Prevent SSRF in redirect expansion
**Vulnerability:** The `api/enrich.ts` endpoint was vulnerable to Server-Side Request Forgery (SSRF) when expanding short Google Maps links. It accepted any arbitrary URL from user input, and blindly followed redirects returned by the `Location` header without validating the protocol or hostname.
**Learning:** Even if the initial user-provided link seems harmless, redirects can be chained to reach internal IPs or services, potentially bypassing firewalls. Additionally, naive string matching (e.g. `.startsWith`) is insufficient for domain validation as it can easily be bypassed (e.g. `google.attacker.com`).
**Prevention:** Always use the `URL` constructor to parse URLs. Implement strict protocol checks (`http:` and `https:`) and precise domain validation (exact matches, `.endsWith` for subdomains, or regex for regional variations) on *every* URL fetched, including both the initial input and any subsequent URLs found in `Location` headers.
