## 2024-10-03 - SSRF and Information Leak via URL Enrichment Open Redirect
**Vulnerability:** The `/api/enrich` endpoint was vulnerable to Server-Side Request Forgery (SSRF). The endpoint expanded user-provided Google Maps short links by following HTTP redirects using `fetch(current, { redirect: "manual" })`. It failed to validate the redirect destination `Location` header, allowing an attacker to supply a seemingly innocuous URL that redirects the Vercel Serverless Function to arbitrary internal IP addresses or local services. Furthermore, any resulting network exceptions or errors returned full stack traces, exacerbating the information leak.
**Learning:** Naively following manual HTTP redirects in a backend service by looping over the `Location` header is unsafe unless *every* intermediate redirect URL is strictly validated against a known allowlist of safe domains and expected protocols.
**Prevention:** Implement an `isSafeUrl` function that strictly checks the URL scheme (only `http:` or `https:`) and matches the host against a rigid allowlist (e.g., `maps.app.goo.gl`, `g.page`, `google.com`, `.google.com` ending). Invoke this validation both before every `fetch` in the redirect loop and on the final resolved URL. Ensure global try-catch blocks return generic `500` error messages or safe specific `400` errors instead of raw exceptions.
