## 2024-05-18 - Prevent Server-Side Request Forgery (SSRF) in Outbound URL Expansion
**Vulnerability:** The `/api/enrich` endpoint accepted arbitrary Google Maps URLs to follow redirects using a server-side `fetch`. Because it did not restrict the allowed hostnames, an attacker could provide an arbitrary URL (like `http://169.254.169.254/` to hit internal AWS metadata APIs, or other internal IP addresses) causing the server to make requests to unintended internal or external resources (SSRF).
**Learning:** Any server-side function that accepts a URL from the user and makes outbound requests to it must validate that the domain and protocol are safe and expected, especially when dealing with redirect expansion.
**Prevention:** Always implement strict URL validation using an allowed host whitelist (e.g., verifying `url.hostname` against `maps.app.goo.gl`, `goo.gl`, or `endsWith('.google.com')` and checking `protocol === 'http:' || protocol === 'https:'`) *before* executing the outbound HTTP request. Do this at every step if following redirects manually.
