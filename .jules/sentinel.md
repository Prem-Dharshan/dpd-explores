## 2024-11-23 - SSRF Vulnerability in URL Redirect Expansion
**Vulnerability:** The `expandUrl` function in `/api/enrich` blindly followed HTTP redirects for any URL supplied by the user via the `url` parameter. By default, `fetch()` in Node.js respects `redirect: "manual"` in terms of handling the redirect directly in code, but then fetching the target without host validation allows for Server-Side Request Forgery (SSRF). An attacker could input a URL hosted on their own server that redirects to internal infrastructure (e.g. metadata endpoint like `http://169.254.169.254` or internal services on `http://localhost`). The `expandUrl` would then perform a GET request against that internal target.
**Learning:** Even when the primary business logic is designed for external public APIs (like Google Maps), manual redirect following logic must include strict allowlists. Naive string matching like `.startsWith('google.')` is insufficient as it allows domains like `google.attacker.com`.
**Prevention:** Implement strict URL parsing and hostname validation. When expecting Google domain redirects, use exact matches (`maps.app.goo.gl`), `.endsWith('.google.com')` strictly for subdomains, and precise regular expressions like `/^((www|maps|consent)\.)?google\.[a-z]{2,3}(\.[a-z]{2})?$/` to properly validate regional top-level domains. Verify the initial URL and *every subsequent URL* extracted from the `Location` header before issuing a fetch.
