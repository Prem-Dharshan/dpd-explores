## 2024-07-22 - SSRF in Maps Link Expansion
**Vulnerability:** The `/api/enrich` endpoint accepted arbitrary URLs and expanded them by following redirects (for up to 5 hops) without validating the domain at each step. This allowed an attacker to supply a malicious URL that could redirect the server to internal endpoints or unapproved external domains, leading to Server-Side Request Forgery (SSRF).
**Learning:** URL shortener expansion is a common vector for SSRF. It is not sufficient to only check the initial URL. A malicious shortener could be set up to redirect to an internal IP address (like `http://169.254.169.254` or `http://localhost`). We must validate the domain of the URL before every single request in the redirect chain.
**Prevention:** Always maintain a strict allowlist of permitted hostnames (e.g., `maps.app.goo.gl`, `google.com`) and enforce that `new URL(url).hostname` matches an allowed host *before* making any outbound `fetch` request, including following `location` headers during redirects.
