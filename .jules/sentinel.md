## 2025-05-15 - CRITICAL SSRF in Google Maps link enrichment
**Vulnerability:** The `/api/enrich` endpoint blindly fetched URLs provided via user input (and recursively followed redirects in `expandUrl`), leading to Server-Side Request Forgery (SSRF). Attackers could submit internal URLs (e.g. `http://169.254.169.254` on AWS or internal network IPs) and extract sensitive instance metadata or internal data.
**Learning:** Manual redirect handling combined with unvalidated user input URLs creates open-redirect SSRF vulnerabilities. Naive string matching like `.startsWith('google.')` is insufficient for domain validation as it permits malicious domains like `google.attacker.com`.
**Prevention:** Always use the `URL` constructor to reliably extract hostnames. Implement strict protocol validation (`http:`/`https:`) and precise hostname validation (e.g., exact matches for `maps.app.goo.gl` or regex checking for regional Google domains) BEFORE calling `fetch` on the initial URL or any subsequent redirect `Location`.
