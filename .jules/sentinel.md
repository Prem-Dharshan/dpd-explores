## 2024-09-14 - Prevent Open-Redirect SSRF Bypass in URL Fetching
**Vulnerability:** The `expandUrl` function in `api/enrich.ts` manually followed redirects without verifying the destination URL after each redirect. This could allow an attacker to provide a legitimate Google Maps URL that redirects to an internal server or malicious site, leading to Server-Side Request Forgery (SSRF). Additionally, simple string matching (like `.startsWith('google.com')`) might allow bypassing the check with subdomains like `google.com.attacker.com`.
**Learning:** When manually handling HTTP redirects (using `redirect: "manual"` in `fetch`), it is critical to validate not just the initial URL but also *every subsequent URL* extracted from the `Location` header. Validation should use strict hostname matching (e.g. exact match, proper `.endsWith` for subdomains, or precise Regex) rather than naive string searches, and enforce expected protocols (`http:`, `https:`).
**Prevention:** Always implement a dedicated URL validation function (e.g., `isValidGoogleMapsUrl`) that checks both protocol and hostname strictly. Invoke this function before making the initial fetch and before fetching any subsequent URLs found in redirect headers. Ensure error handlers (`catch` blocks) do not leak raw error strings or stack traces by always returning safe generic messages (e.g. "An error occurred").
