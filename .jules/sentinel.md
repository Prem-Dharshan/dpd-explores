## 2024-05-24 - SSRF vulnerability in Maps URL expansion
**Vulnerability:** A Server-Side Request Forgery (SSRF) vulnerability existed in `api/enrich.ts` due to following redirects (via `expandUrl`) on user-supplied URLs without any protocol or hostname validation. This could allow an attacker to bypass firewalls and make requests to internal services or malicious external domains. Additionally, error handling in the same file leaked unhandled stack traces by sending `String(e)` to the client.
**Learning:** When expanding user-provided shortened URLs, manually following redirects without re-validating the resolved URL at each step creates a significant SSRF vector. Simple `.startsWith()` checks are insufficient for domain validation as they can be bypassed (e.g., `google.attacker.com`).
**Prevention:** Implement strict protocol (`http:`/`https:`) and hostname validation (e.g., exact match, `.endsWith('.google.com')`, or precise regexes) on the initial input URL AND on every subsequent redirect URL before fetching it. Fail securely with a generic error message if validation fails, preventing stack trace leakage.
