## 2025-02-18 - SSRF Vulnerability in URL Redirect Expansion
**Vulnerability:** The `/api/enrich` endpoint expanded shortened URLs (like Google Maps links) without validating the protocols or hostnames of the initial URL or the subsequent redirect locations. This allowed for Server-Side Request Forgery (SSRF).
**Learning:** URL redirect expansion inherently acts as a proxy fetching potentially untrusted inputs. Relying only on frontend validation or assuming inputs will be legitimate short links is unsafe. Missing validation can lead to fetching internal resources (e.g. localhost, AWS metadata via HTTP/file protocols).
**Prevention:** Always implement explicit, strict protocol validation (only `http:` and `https:`) and whitelist allowed domains/hostnames (e.g. using exact matching, `.endsWith('.google.com')` for subdomains, and precise regexes for regional domains) both before initiating the request and inside the loop fetching redirect locations. Avoid naive substring matching like `.startsWith('google.')`. Return generic server errors in the top-level catch block to avoid leaking underlying network errors.
