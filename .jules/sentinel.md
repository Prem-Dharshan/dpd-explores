## 2024-05-18 - SSRF Vulnerability in URL Redirect Expansion
**Vulnerability:** The `/api/enrich` endpoint accepted user-provided URLs and followed redirects using `fetch(..., { redirect: "manual" })` to expand shortened Google Maps links. It blindly followed the `Location` header without validating the protocol or hostname, allowing an attacker to supply a URL that redirects to internal infrastructure or malicious endpoints (Server-Side Request Forgery).
**Learning:** Even when functionality dictates following redirects, strict whitelist validation must be applied to the initial URL and *every subsequent URL* extracted from the `Location` header. A naive `startsWith` check is insufficient for whitelisting; explicit host checks or strict regexes are required.
**Prevention:** Implement a strict URL validator that enforces `http:` or `https:` protocols and checks the hostname against an explicit allowlist (e.g., exact matches for `maps.app.goo.gl` and strict regex matching for `google.com` regional domains) before invoking `fetch`. Apply this validator recursively on any redirected URLs.
