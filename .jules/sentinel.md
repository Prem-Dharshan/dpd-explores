## 2024-10-24 - SSRF Vulnerability in Google Maps URL Expansion
**Vulnerability:** The `/api/enrich` endpoint accepted user-provided URLs and manually followed their redirects via `fetch(url, { redirect: "manual" })`. It completely lacked validation for both the initial input URL and the subsequent `Location` header redirect URLs, making it vulnerable to Server-Side Request Forgery (SSRF) bypasses (e.g. allowing arbitrary requests to internal IPs if the URL redirected there, or allowing arbitrary `file:` or non-HTTP protocols).
**Learning:** Even when the intended use case is simply to "expand a shortened link" (like `maps.app.goo.gl`), every step of the redirect chain must be verified. Simply checking the initial URL is insufficient since a safe-looking URL could immediately redirect to a malicious internal endpoint. Error handling also previously leaked potentially sensitive details by converting errors to raw strings instead of failing securely.
**Prevention:** Always implement strict protocol checking (only allow `http:` and `https:`) and whitelist allowed hostnames dynamically. Use precise matching for hostnames (e.g., exact matches, `.endsWith()` with safe suffixes, or tight regex for regional domains) rather than broad `.includes` or `.startsWith` methods. Apply validation constraints sequentially on *every* new URL encountered in a redirect chain, and ensure global try-catch blocks fail securely with generic error messages.
