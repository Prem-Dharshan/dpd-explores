## 2024-05-18 - SSRF Vulnerability in API Redirect Expansion
**Vulnerability:** The `/api/enrich` endpoint accepted arbitrary URLs, and the `expandUrl` function followed redirects indiscriminately without validating the host. This meant it could be coerced into hitting internal networks or fetching content from arbitrary attacker-controlled servers (SSRF).
**Learning:** Naive URL expansion logic needs careful vetting, especially when expanding short links that might redirect anywhere. Simply checking the initial URL string is insufficient; redirect hops must also be validated to ensure they still belong to allowed domains. Additionally, string manipulation (like `.startsWith()`) for host checking can be easily bypassed (e.g., `google.attacker.com`); strict matching and regexes are necessary.
**Prevention:** Implement strict URL validation on the initial URL and *every* subsequent redirect hop. Only allow `http:` or `https:` protocols, and use exact matching or careful regexes to validate the hostname (e.g., `maps.app.goo.gl` or `*.google.com` regional domains) rather than loose string searches.
