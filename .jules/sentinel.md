## 2024-05-20 - SSRF and Open Redirect in Google Maps Link Expansion
**Vulnerability:** The `/api/enrich` endpoint accepted user-provided Google Maps URLs and followed redirects (`redirect: "manual"`) using `fetch` to extract full coordinate/place details without validating the target domains.
**Learning:** Even when intending to just "follow a Google Maps link", blindly requesting user-provided URLs and following the `Location` header can lead to Server-Side Request Forgery (SSRF). An attacker could provide a link to a malicious server, which then returns a 3xx redirect to an internal IP (like metadata services or local network resources), bypassing naive URL filtering.
**Prevention:** Strictly validate the protocol (`http/https`) and the exact domain/hostname (using strict allowlists like `maps.app.goo.gl` or explicit regexes for regional domains) for both the *initial* URL and *every* subsequent URL extracted from a `Location` header during manual redirect resolution.
