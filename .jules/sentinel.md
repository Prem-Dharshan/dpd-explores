## 2024-05-24 - SSRF in Server-Side URL Redirection
**Vulnerability:** A Server-Side Request Forgery (SSRF) vulnerability existed in `api/enrich.ts`'s `expandUrl` function, where a user-provided URL (`maps.app.goo.gl`) was directly fetched by the server without any validation. Furthermore, it followed `location` headers dynamically without re-evaluating trust on each subsequent redirect. This allowed potentially accessing internal server infrastructure or performing unauthorized HTTP requests from the server's context. There was also an information disclosure vulnerability where `String(e)` output raw stack traces directly into 500 error responses on the same endpoint.
**Learning:** Even when standard APIs (like Google Places) are eventually queried, any custom code that acts as an intermediate proxy/fetcher must implement strict input validation on hostnames and explicit controls on redirect handling (like `redirect: "manual"`) coupled with verification at each redirect hop.
**Prevention:** Always maintain a whitelist of allowed hostnames (e.g., `maps.app.goo.gl`, `goo.gl`, `maps.google.com`) when fetching URLs via a server-side route. Verify the hostname both on the initial user-provided URL and against the location provided during each manual redirect. Return generic 500 error messages to clients to prevent leaking application state or infrastructure details.
