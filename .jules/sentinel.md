## 2024-10-26 - SSRF via Manual Redirect Handling
**Vulnerability:** The `/api/enrich` endpoint accepted user-provided URLs and manually followed redirects using `fetch(url, { redirect: "manual" })`. It blindly trusted the `Location` header to construct the next URL, allowing an attacker to bypass initial naive domain checks (if any) by providing a safe URL (like a mock google redirect) that responds with a redirect to an internal IP (e.g., `http://169.254.169.254` or `http://localhost:3000`).
**Learning:** When handling manual redirects to expand shortened URLs, validating only the initial input URL is insufficient. Attackers can control the `Location` header of the redirect response.
**Prevention:** Always validate every URL in the redirect chain before issuing the next request. Use the `URL` constructor to reliably extract the protocol and hostname, strictly enforce `http:`/`https:` protocols, and use exact matching or strict regex to validate allowed hostnames against an allowlist, avoiding naive string methods like `.startsWith()`.
