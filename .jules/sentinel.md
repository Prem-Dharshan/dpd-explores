## 2024-10-01 - SSRF Vulnerability in manual redirect handling
**Vulnerability:** A Server-Side Request Forgery (SSRF) risk existed in `/api/enrich.ts` where unauthenticated users could provide an arbitrary URL, and the server would manually follow redirects (`redirect: "manual"`) by issuing GET requests to the locations without checking the destination.
**Learning:** When using `fetch` with manual redirect following, it is not sufficient to just validate the initially provided URL. Every subsequent URL extracted from the `Location` header must also be strictly validated. Furthermore, simple string matching (like `.startsWith('google.')`) allows bypasses via malicious domains (e.g., `google.attacker.com`).
**Prevention:** Implement an explicit validation function that restricts protocol to `http`/`https` and enforces exact hostname matches (e.g., `maps.app.goo.gl`) or safe regexes (for regional domains). Call this validation function in the loop *before* issuing any GET request.
