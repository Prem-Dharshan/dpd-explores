## 2024-09-28 - [CRITICAL] Fix SSRF vulnerability in URL enrichment
**Vulnerability:** The `/api/enrich` endpoint accepted user-provided Google Maps URLs and followed HTTP redirects up to 5 times. It did not validate the protocol or hostname of either the initial URL or the subsequent redirect locations, leading to a potential open-redirect SSRF (Server-Side Request Forgery) vulnerability where a seemingly safe domain could redirect the server to an internal IP or malicious service.
**Learning:** Even when manually handling redirects with `redirect: "manual"`, every step of the redirect chain must be strictly validated against an allowlist of domains and protocols. Naive hostname checks (e.g., `startsWith("google.")`) are insufficient and easily bypassed.
**Prevention:** Always implement explicit protocol validation (allowing only `https:`) and strict hostname regex validation for any endpoint that fetches external URLs. Every URL extracted from a `Location` header must be passed through the same rigorous validation before being fetched.
