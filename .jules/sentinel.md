## 2024-05-24 - SSRF in URL Expansion
**Vulnerability:** The `/api/enrich` endpoint accepted arbitrary Google Maps URLs and followed redirects using `fetch` with `redirect: "manual"` without validating the hostnames of the subsequent redirect locations. This allowed Server-Side Request Forgery (SSRF).
**Learning:** Even if an initial URL appears to be a safe shortlink, following manual redirects must re-validate every new URL against a strict whitelist (e.g. valid domains/protocols) to prevent an attacker from redirecting the server to internal IP addresses (e.g., cloud metadata endpoints like 169.254.169.254). Validating Google domains requires precise regex matching, not naive string operations like `.startsWith('google.')` which allow bypasses.
**Prevention:** Implement an `isSafeUrl` function that strictly checks allowed protocols (`http:` / `https:`) and hostnames using exact matches, `.endsWith` for subdomains, and precise regexes for regional domains. Call this validation on both the initial input and every URL encountered during the redirect chain in `expandUrl`.
