## 2025-03-09 - SSRF and Information Leakage in Google Maps Enrichment API
**Vulnerability:** The `api/enrich.ts` endpoint followed redirects from user-provided URLs without validating the protocol or domain, leading to a Server-Side Request Forgery (SSRF) bypass where external links could redirect to internal IPs. Additionally, errors in the endpoint were exposed directly to clients via `String(e)`, leaking internal details.
**Learning:** Naively following redirects (even with `redirect: "manual"`) without strict validation allows SSRF. Validating only the initial URL is insufficient; every URL in a redirect chain must be checked against an allowlist of domains and protocols. Error catch blocks in API endpoints often leak stack traces if exceptions are sent back as strings.
**Prevention:** Implement strict URL validation functions (e.g., checking `http:`/`https:` protocols and exact/regex matching for hostnames) and apply them to both the initial URL and every subsequent URL extracted from the `Location` header. Ensure catch blocks in API endpoints fail securely by returning generic error messages (e.g., `"An error occurred"`).
