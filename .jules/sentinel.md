## 2025-03-09 - [Prevent SSRF on Open Redirects in URL Expansion]
**Vulnerability:** The `/api/enrich` endpoint expanded shortened URLs (like `maps.app.goo.gl`) using a manual redirect loop. While fetching the initial URL or subsequent redirects, it did not enforce any protocol or domain validation. An attacker could exploit this by providing a short link (or a redirect URL in the `Location` header) that ultimately points to an internal network IP (e.g., `http://169.254.169.254` or `http://localhost:5432`), leading to an SSRF vulnerability.
**Learning:** Manual redirect-following code (e.g. `fetch(url, { redirect: "manual" })`) can blindly navigate to internal services or arbitrary attacker domains if the redirected URLs (`Location` header) are not validated at every step of the loop.
**Prevention:** Always validate not just the initial input URL, but every single URL extracted from a `Location` header during manual redirect resolution. Use `new URL()` to parse the URL safely, check that the protocol is explicitly `http:` or `https:`, and ensure the hostname belongs to a strict whitelist (e.g., using precise regex or exact domain matching like `maps.app.goo.gl` or `.google.com` suffixes) before proceeding to make a request.
