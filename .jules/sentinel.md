## 2024-05-18 - Prevent SSRF in Google Maps enrich API
**Vulnerability:** The `/api/enrich` endpoint accepted arbitrary URLs via the `url` payload property and used a manual redirect following script (`expandUrl`) that would blindly fetch any URL returned in the `Location` header. This constituted an SSRF vulnerability where an attacker could provide an initial valid URL that redirects to internal endpoints (e.g. `http://localhost/` or cloud metadata IPs), thus scanning the internal network or accessing sensitive metadata.
**Learning:** Even if an initial user-provided URL looks benign or points to an external site, manual redirect logic requires strict validation at *every step* of the redirect chain to prevent SSRF bypasses via open redirects on external domains.
**Prevention:** Implement an explicit allowlist validation step (like `isValidGoogleUrl` validating `http:`/`https:` protocols and exact Google Maps hostnames/patterns) before calling `fetch()` on the initial URL and before fetching every subsequent URL found in `Location` headers.
