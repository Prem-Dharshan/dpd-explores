## 2024-08-12 - [CRITICAL] Prevent SSRF by Explicit Hostname and Protocol Validation in URL Resolvers
**Vulnerability:** The `expandUrl` function in `api/enrich.ts` followed redirects based on user-supplied URLs blindly without protocol checking or hostname whitelisting. This allows Server-Side Request Forgery (SSRF) vulnerabilities, where a malicious user could submit a URL pointing to internal services or non-HTTP protocols, and the server would perform requests on their behalf.
**Learning:** Even when a function's intended use is narrowly focused (e.g., following `maps.app.goo.gl` redirects), the actual implementation (a generic `fetch` loop following the `location` header) must be defensively constrained. Attackers can provide URLs that redirect to unexpected targets.
**Prevention:** Always implement explicit protocol validation (e.g., enforcing only `http:` and `https:`) and strict hostname validation (whitelisting only the necessary and expected domains) at every step of a redirect loop or any outbound server fetch using user-supplied URLs.
