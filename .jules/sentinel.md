## 2025-07-25 - [CRITICAL] Fix SSRF Vulnerability in enrich.ts
**Vulnerability:** The `/api/enrich` endpoint contained a Server-Side Request Forgery (SSRF) vulnerability. The `expandUrl` function allowed arbitrary users to submit a URL, which the server would `fetch` and blindly follow up to 5 manual redirects without any domain validation.
**Learning:** Outbound network requests to user-provided URLs in serverless functions (like Vercel functions in `/api`) must strictly validate hostnames. Even if a URL initially appears safe, manual redirect loops (`fetch` with `redirect: "manual"`) can be manipulated to redirect internal API requests to malicious or private internal infrastructure.
**Prevention:** Implement strict URL validation using the `URL` constructor (to prevent parser mismatches) and ensure the hostname matches an explicit whitelist (e.g., `maps.app.goo.gl`, `www.google.com`). This validation must occur not just on the initial URL, but dynamically on every intermediate location header returned during a manual redirect loop.
