## 2024-06-11 - SSRF Vulnerability in Maps URL Enrichment
**Vulnerability:** The `/api/enrich` endpoints (both Vercel Serverless and Vite SSR handlers) expanded Google Maps URLs by blindly following HTTP redirects. The URL parameter and intermediate `Location` headers were not validated before making an outbound `fetch` request, leaving the server vulnerable to Server-Side Request Forgery (SSRF) and allowing an attacker to ping arbitrary internal or external services via malicious redirects.
**Learning:** Even when a feature specifically asks for external links (like Google Maps URLs), the hostnames must be strictly whitelisted. Importantly, validation must occur not just on the initial user input but *within* the redirect loop itself, as a benign-looking initial URL could redirect to a malicious internal address.
**Prevention:** Implement strict hostname whitelisting. Check both the initial URL and any intermediate URLs encountered while following redirects. Fail securely by returning generic 500 errors so internal errors don't leak information to the client.
