## 2026-10-19 - [Open-Redirect SSRF Bypass in URL Expansion]
**Vulnerability:** The `/api/enrich` endpoint accepted arbitrary user-provided URLs and followed their redirects using `fetch(current, { redirect: "manual" })` up to 5 times. Because the domain was not validated *during* each redirect hop, an attacker could supply an innocent-looking starting domain that redirects to internal IP addresses or arbitrary malicious sites, executing a Server-Side Request Forgery (SSRF).
**Learning:** SSRF protections can be bypassed via open redirects if validation is only performed on the initial user input. The `Location` header returned by the server is untrusted data and could point to internal infrastructure (e.g., `169.254.169.254` or `127.0.0.1`).
**Prevention:** Always implement strict, explicit protocol and hostname validation before every HTTP request, not just the initial input. Use `new URL()` to safely extract and validate hostnames to prevent bypasses, and ensure validation occurs inside the redirect loop before each `fetch` call.
