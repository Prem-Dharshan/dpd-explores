## $(date +%Y-%m-%d) - React Router searchParams Array Instability Breaks Memoization
**Learning:** `searchParams.getAll()` from `react-router-dom` returns a new array reference on every render, even if the underlying search params haven't changed. When wrapped in a `useCallback` that is immediately invoked in the render body, or when passed directly as an array dependency to `useMemo`, this causes continuous expensive re-evaluations.
**Action:** When filtering data based on URL arrays (like `vibeFilter` or `occasionFilter`), use `useMemo` (not `useCallback` + invocation) and stabilize the array dependencies by stringifying them first (`const stringifiedVibe = JSON.stringify(vibeFilter)`). Use `// eslint-disable-next-line react-hooks/exhaustive-deps` to bypass the ESLint warning that wants the raw array reference.
