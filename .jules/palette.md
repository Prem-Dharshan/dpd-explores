## 2025-02-18 - Ensure fully semantic accessibility for custom interactive elements
**Learning:** When using non-semantic elements like `<img>` tags as interactive controls (e.g. the user avatar acting as a sign-out trigger in the dashboard), simply adding an `onClick` handler is severely limiting for keyboard and screen reader users. Additionally, icon-only buttons (like carousel arrows or clear input toggles) fail accessibility tests without explicitly defined text alternatives.
**Action:** Always verify that interactive non-semantic elements have full keyboard accessibility affordances, including `role="button"`, `tabIndex={0}`, `onKeyDown` handlers supporting Enter and Space keys, and explicit visual focus indicators via `focus-visible` utility classes (e.g. `focus-visible:ring-2 focus-visible:ring-accent focus-visible:outline-none`). For icon-only button elements, actively provide descriptive `aria-label` attributes to ensure context is conveyed to assistive technology.
