## 2024-05-24 - Interactive Non-Semantic Elements Require Explicit Keyboard Affordances
**Learning:** When using non-semantic elements like `<img>` tags as interactive controls (e.g., as a sign-out button via the user avatar), users navigating via keyboard cannot reach or activate them by default. This creates a significant accessibility barrier. Simply adding an `onClick` handler is insufficient.
**Action:** When a non-semantic element must be interactive, explicitly add `role="button"`, `tabIndex={0}`, an `onKeyDown` handler to capture 'Enter' and 'Space' keys, and a `focus-visible` utility class (e.g., `focus-visible:ring-2 focus-visible:ring-accent focus-visible:outline-none`) to ensure both functional keyboard access and visual focus indication. Where possible, wrap the element in a native `<button>` instead.
