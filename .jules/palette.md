## 2024-05-24 - Accessibility for Icon-only Buttons and Non-semantic Interactive Elements
**Learning:** Icon-only buttons lacking `aria-label`s fail screen readers. Additionally, when non-semantic elements like `<img>` are used as interactive controls (e.g., user avatars functioning as buttons), they fail keyboard accessibility. To make a non-semantic element fully accessible, it requires not only a click handler but also `role="button"`, `tabIndex={0}`, an `onKeyDown` handler (listening for 'Enter' or 'Space'), an `aria-label`, and explicit focus styling (e.g. `focus-visible:ring-2 focus-visible:ring-accent focus-visible:outline-none`).
**Action:** When adding or auditing icon-only controls, always include `aria-label`s and `focus-visible` styles. If a non-semantic element like an `<img>` or `<div>` must act as a button, rigorously apply the full suite of keyboard accessibility properties (`role`, `tabIndex`, `onKeyDown`) rather than just an `onClick` handler. Alternatively, wrap the image in a native `<button>` element.
