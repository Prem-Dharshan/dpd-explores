## 2026-11-05 - Keyboard Accessibility for Non-Semantic Elements and Overlays
**Learning:** When using non-semantic elements like `<img>` tags as interactive elements (e.g., user avatars clicking to sign out), mouse users can use them, but keyboard and screen reader users cannot unless they are given full keyboard accessibility affordances: `role="button"`, `tabIndex={0}`, an `onKeyDown` handler (for Enter/Space, preventing default on Space), and explicit `focus-visible` styles. Additionally, controls overlaid on dynamic backgrounds like photo carousels need high contrast focus rings (e.g., `focus-visible:ring-surface`) to remain visible against varied images.
**Action:** When creating custom interactive components or converting non-interactive elements into clickable targets, actively implement full keyboard accessibility support alongside mouse events. Use context-appropriate contrast colors for focus outlines on overlays.
