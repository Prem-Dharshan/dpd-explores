## 2024-10-18 - Ensure robust keyboard navigation for non-semantic interactive elements
**Learning:** Found several instances where non-semantic tags (like `img`) were used as buttons (e.g., user avatars), or icon-only buttons lacked proper ARIA labels. Users relying on keyboard navigation couldn't access or interact with these effectively, and screen readers lacked context for icon-only buttons.
**Action:** When converting non-semantic elements like `img` or `div` into interactive buttons, ensure they receive full keyboard accessibility affordances: `role="button"`, `tabIndex={0}`, an `onKeyDown` handler covering Enter and Space, and explicit `focus-visible` utility classes (e.g., `focus-visible:ring-2 focus-visible:ring-accent focus-visible:outline-none`) for visual focus. Additionally, ensure all icon-only buttons have descriptive `aria-label` attributes.
